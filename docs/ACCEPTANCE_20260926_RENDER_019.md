# v0.1.9 原生背景黑边修复验收

## 原因与修复

v0.1.8 将中央内容区改为有外边距的白色圆角面板，外边距与圆角之外没有被面板填充。`eframe::App::clear_color` 默认返回半透明暗色（实际 RGBA 为 9/255、9/255、9/255、180/255），在此原生窗口上显示为黑色。不是网卡或显卡驱动的诊断结论。

PanelApp 现在明确返回不透明 `#F0F4F9`；原生 ui_capture 示例委托同一实现。离屏 JSON 保存实际清屏色，CPU 光栅器从该字段初始化画布，不再使用固定白底。上一版白底预览掩盖了缺陷，本次修正验证路径。

## 回归证据

- `native_canvas_is_opaque_material_surface` 在旧实现失败，报告暗色半透明值；修复后通过，覆盖浅色与深色系统视觉输入。
- 全工作区离线锁定测试 969 项通过；Clippy 全目标 `-D warnings`、格式、差异空白与 MSIX dry-run 通过。
- 使用 Computer Use 技能检查真实 Windows 窗口：在原 v0.1.8 复现两侧黑边；正常退出后打开本轮 release 面板，确认同一位置黑边消失。没有强制结束进程。
- 原生窗口检查时模块未连接；没有发送/删除短信、安装驱动或更改网卡设置。
- 用户截图中的“应用发生内部错误”未能在启动和刷新中复现，现有日志没有定位该提示的稳定错误码；本轮不声称已修复该独立提示。
