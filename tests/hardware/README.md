# tests/hardware — 真实硬件（HIL）验收程序与报告索引

Hardware-in-the-loop (HIL) acceptance procedures for the DJI first-generation 4G module panel (`USB\VID_2CA3&PID_4006`). 本目录文件为验收程序与报告模板，不包含任何自动化测试代码。

依据文档（本目录内容不得与其矛盾）：

- `docs/AI_HANDOFF_2026-09-04.md` 第 7 节（7.2 / 7.3 / 7.4）与第 9 节。
- `docs/superpowers/specs/2026-09-03-dji4g-gen1-panel-design.md`（功能与修复范围）。

## 1. 目的与范围

本目录定义针对**大疆一代 4G 模块（精确设备身份 `USB\VID_2CA3&PID_4006`，且必须绑定到该模块的精确网卡）**的真实硬件验收程序。这些项目会**读取或改变真实设备/网络状态**（识别、SIM/注册/附着读取、DHCP/DNS/网卡重启/设备重新枚举/USB 网络模式/APN/模块重启等受控修复、Windows 移动热点开关、UAC 提权 helper），因此**自动化测试不能替代**本目录的人工或硬件验收。

范围对应交接文档第 7 节的三部分：

- 7.4：PID4006 真实硬件 HIL（下表 A 组）。
- 7.3：UAC/helper 验收（下表 B 组）。
- 7.2：UI/生命周期人工验收（下表 C 组）。

## 2. 授权前提（必读）

> **HIL 验收在没有用户明确授权之前不得执行。**
>
> 7.4 全部项目会读取或改变真实设备/网络状态，必须先得到用户针对以下两点的**明确授权**：
>
> 1. **维护窗口**：允许在指定时间段内对模块与网络执行状态变更操作；
> 2. **测试 SIM/测试设备**：允许使用用户指定的测试 SIM 卡与测试模块/整机，而不是生产在用设备。
>
> 每份报告必须填写“前置授权确认（维护窗口/测试 SIM 已获用户授权：是/否）”。未获授权时，相应项目只能记为 `Unexecuted`，不得以任何形式变通执行。

## 3. 安全规则

1. **不能自动重试不可重复操作。** 所有写操作必须遵循：重新枚举目标 → 校验 epoch/身份/操作前状态 → 用户确认 → 只执行一次 → 新鲜回读 → `Applied / Failed / OutcomeUnknown` 三态结果。写超时是 `OutcomeUnknown`，不得在未获新的用户确认计划前重发。
2. **一次只执行一个操作。** 同一时间只允许一个受控修复/热点/提权操作在进行；上一个操作未得出三态结论前不得发起下一个。
3. **任何安全边界被突破时立即停止并记录 `Failed`。** 停止条件与交接文档第 9 节一致，包括：
   - 普通启动仍使用 fake/demo 或生产端口固定返回占位错误；
   - 能匹配非 `VID_2CA3&PID_4006` 设备，或使用 FriendlyName/默认路由兜底；
   - 热点、修复动作缺少 fresh identity/epoch/before-state 校验；
   - 用户取消 UAC 后仍执行，或 outcome unknown 被自动重试；
   - 手机热点/TUN 的公网结果被记为大疆模块可用；
   - 日志/界面泄露敏感标识，或 package/helper 信任边界被放宽。
4. **证据脱敏。** 所有截图、日志、导出报告中必须对敏感值脱敏：APN、IMEI、ICCID、手机号码、SSID、设备序列号、nonce、pipe 名、以及可识别用户身份的 IP 地址。脱敏写法示例：`<REDACTED>`、`USB\VID_2CA3&PID_4006\<REDACTED>`。每份报告必须勾选“敏感值脱敏确认”。
5. 只允许一代 PID 白名单内的操作；禁止任意 AT 命令、任意 shell、模糊 FriendlyName 匹配、驱动或固件修改。

## 4. 四态结论词汇（唯一允许的结论）

每个测试项的结论只能是以下四种之一：

| 结论 | 含义 |
| --- | --- |
| `Passed` | 已**实际执行**，观察结果满足预期。 |
| `Failed` | 已**实际执行**，结果不满足预期，或触发第 3 节任一停止条件。 |
| `Environment-blocked` | 尝试执行但被工具/硬件/环境缺失阻塞（例如缺少测试 SIM、缺少已签名安装的 helper、缺少指定 Windows 版本机器）。**绝不伪造通过。** |
| `Unexecuted` | 未实际执行。**任何未实际执行的项都是 `Unexecuted`**；自动化测试不能替代人工或硬件验收。截至交接时，真实设备 HIL、UAC 与人工 UI/生命周期项目均为 `Unexecuted`。 |

判定规则（交接文档第 9 节）：只有在必需项全部 `Passed`，且剩余 `Environment-blocked`/`Unexecuted` 均被用户明确接受时，才可称为“最终验收通过”；在此之前只能称“发布候选”。

## 5. 如何使用 `report-template.md`

1. **每个测试项复制一份** `tests/hardware/report-template.md`，建议命名为 `tests/hardware/reports/<编号>-<简述>-<YYYYMMDD>.md`（编号对应下文索引，如 `A04`、`B02`、`C01`）。
2. **填写每一个字段**，不得留空或删字段：测试项、执行时间（含时区）、commit、Windows 版本、安装方式（MSIX/便携/开发）、模块硬件 ID（脱敏）、驱动版本、连接方式（直插/扩展坞/具体 USB 口）、Clash/Meta/TUN 状态、前置授权确认、步骤、预期、实际、截图/日志位置、敏感值脱敏确认、四态结论、备注。
3. **附上证据位置**：截图、日志、诊断导出文件的路径或链接写在“截图/日志位置”字段；证据本身必须已按第 3 节脱敏。
4. 把该份报告的四态结论回填到下文索引对应行的“四态结论”列，并链接报告文件。
5. 一个测试项内包含多个子场景（如“IPv4/IPv6 分别记录”“成功/失败/拔插竞态/UAC 取消/结果未知”）时，在“步骤/实际”中逐项分开记录；任一子场景失败则整个测试项结论为 `Failed`，被环境阻塞且无法执行的子场景需在备注中说明。

模板中附有一条**示例**行，仅使用伪造/脱敏值，供格式参考，不是真实执行结果。
